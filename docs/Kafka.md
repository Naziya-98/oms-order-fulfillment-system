# Kafka

## Overview

Apache Kafka is used for asynchronous communication between services.

Services publish business events and consume events generated by other services. This keeps the services loosely coupled while allowing the order workflow to progress.

---

# Communication Patterns

The project contains two independent messaging flows.

- Saga Choreography
- Saga Orchestration

Each implementation uses a separate set of Kafka topics.

---

# Producer Services

The following services publish Kafka events.

- Order Service
- Inventory Service
- Payment Service
- Notification Service
- Orchestrator Service

---

# Consumer Services

Kafka events are consumed by the participating services based on the workflow being executed.

Each service listens only to the topics required for its business responsibility.

---

# Event Processing

A typical event flow is:

1. Service performs business operation.
2. Event is published.
3. Kafka delivers the event.
4. Interested services consume the event.
5. Workflow continues.

Detailed event sequences are documented separately in:

- Saga-Choreography.md
- Saga-Orchestration.md
